# Metrics Dictionary

Документ фиксирует технические определения продуктовых метрик, используемых в анализе раннего пользовательского пути Flood-It!.

Основной объект анализа — новые пользователи, представленные в таблице `users`.

## 1. New users

Новый пользователь — пользователь, время первого взаимодействия которого попадает в период формирования анализируемой когорты.

**Источник:** `users`.

## 2. First observed result

Первый наблюдаемый результат пользователя — самый ранний явный результат игровой попытки среди:

- `success`;
- `fail`.

Попытки с `outcome = 'unknown'` не рассматриваются как результативные.

**Источник:** `gameplay_attempts` + `events`.

## 3. Activation

Пользователь считается активированным, если после первого наблюдаемого результата он начинает ещё одну игровую попытку в рамках той же аналитической сессии.

Новая попытка определяется новым `start_event_id` в `gameplay_attempts`.

### Activation rate

Доля пользователей с первым наблюдаемым результатом, которые начали следующую игровую попытку в той же сессии.

`activation_rate = activated_users / users_with_first_result`

## 4. First session depth

Количество результативных игровых попыток пользователя в первой аналитической сессии.

Результативной считается попытка с:

- `outcome = 'success'`;
- `outcome = 'fail'`.

**Первая сессия:** `session_number = 1`.

## 5. Retry after first fail

Метрика рассчитывается только для пользователей, чей первый наблюдаемый результат — `fail`.

Retry фиксируется, если после первого проигрыша пользователь начинает новую попытку в рамках той же сессии того же игрового ключа:

- для progressive mode — того же `level`;
- для quickplay mode — того же `board`.

### Retry rate

`retry_rate = users_with_retry_after_first_fail / users_with_first_fail`

## 6. Same-day return

Метрика отражает возвращение пользователя в отдельную сессию в первый день

- первая сессия пользователя — `session_number = 1`;
- существует сессия `session_number > 1`;
- дата начала этой сессии совпадает с `cohort_date`.

## 7. D1 retention

D1 retention — доля новых пользователей, у которых наблюдается хотя бы одно событие на следующий календарный день после `cohort_date`.

`D1 = retained_D1_users / observable_D1_users`

Пользователи с `cohort_date` в последний календарный день датасета исключаются из знаменателя.

## 8. D7 retention

D7 retention — доля новых пользователей, у которых наблюдается хотя бы одно событие через семь календарных дней после `cohort_date`.

`D7 = retained_D7_users / observable_D7_users`

Пользователи, для которых с даты когорты до конца доступного периода прошло менее семи дней, исключаются из знаменателя.

## 9. Early IAP

Пользователь считается совершившим IAP, если после первого взаимодействия наблюдается событие `in_app_purchase`.

Из-за малого числа покупок метрика используется как exploratory-показатель и не является основной продуктовой метрикой.

## 10. Extra steps / rewarded ads

Для дополнительной продуктовой гипотезы отдельно рассматриваются наблюдаемые события:

- `no_more_extra_steps`;
- `use_extra_steps`;
- `ad_reward`;
- `in_app_purchase` продуктов `extra_steps_pack_*`.
